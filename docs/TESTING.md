# Boltspark verification workflow

Boltspark separates tests that can run on a clean hosted worker from tests that
require the pinned native runtime, a real HWND, and a Direct3D 12 GPU. Test
programs and probes are tracked under `tests/`; generated bytecode, logs,
screenshots, CSV files, and JSON results remain under ignored `bin/test-results/`.

## Portable checks

```powershell
.\tools\tests\test.ps1 -Portable
```

This command does not need Neko, HashLink runtime DLLs, or a GPU. It:

1. enforces the native H2D + `hldx` + DX12 dependency policy;
2. compiles the complete application to HashLink bytecode using the tracked
   source classpaths directly;
3. runs the portable arcball, Euler, post-arcball rotation-ring, BoltUI-core, command-history,
   editor-session, component-system, scene-hierarchy, keybinding-migration,
   play-mode isolation, project/scene-serialization, and Asset Browser data-layer
   tests through the Haxe interpreter.

The pinned compiler executable and its five adjacent Windows runtime DLLs are
tracked as one hash-verified set; native HashLink/DX12 runtime modules remain
designated-machine dependencies and are not required by this portable job.

`.github/workflows/windows-ci.yml` runs this path on every push to `main` and
on pull requests.

## Full local regression suite

```powershell
.\tools\tests\test.ps1
```

The default native path first runs `tools/build.ps1 -Check`, then compiles and
runs all portable tests as HashLink bytecode plus the editor-camera navigation
test, Heaps affine scene-object bridge, DX12 `hl.CArray`, and FreeType
native-module regressions. It expects a previous build to have created
`bin/freetype.hdll`.

To rebuild everything first:

```powershell
.\tools\tests\test.ps1 -Build
```

## Native runtime probes

Optional switches add real-window checks:

```powershell
.\tools\tests\test.ps1 -Build -NativeSmoke -PlayMode -CommandHistory -ComponentRemoval -RotationHandoff -WindowLifecycle -SplitterCapture -DpiProbe -DeviceReset -FocusSelection -FovInput -KeybindingsList -ProjectFiles -AssetBrowser -ImportFiles -ExplorerDrop -UntitledSession
```

| Switch | Coverage |
|---|---|
| `-NativeSmoke` | Development and packaged release HWND creation, icon assignment, positive DX12-driver identity, empty stderr, and clean `WM_CLOSE`. |
| `-PlayMode` | Clicks the transport Play button, pauses/resumes with F6 and stops with F7 in a real DX12 window. Asserts the runtime object count, elapsed time, and that the editor history revision is unchanged across the Play/Stop cycle (`tests/native/Test-PlayMode.ps1`). |
| `-CommandHistory` | Native gizmo, Inspector, Create, and Delete commands followed by rebindable Ctrl+Z/Ctrl+Y; verifies transform, renderer-view, identity, and selection restoration in the running DX12 editor. |
| `-ComponentRemoval` | Clicks the MeshRenderer header remove action on the starter cube and verifies the component detaches, then that Ctrl+Z/Ctrl+Y restore/remove it through command history. |
| `-RotationHandoff` | Window-scoped center arcball followed by a snapped world-axis torus drag; verifies that the ring changes only its captured axis after an arbitrary freeform orientation. |
| `-WindowLifecycle` | Small/large/baseline resize, maximize/restore, minimize/restore, splitter persistence, empty-space deselection, and cube picking after splitter movement. |
| `-SplitterCapture` | A splitter drag takes Win32 mouse capture and releases it on drag end, so a button release outside the editor window still reaches Heaps instead of leaving the splitter stuck. |
| `-DpiProbe` | Current-monitor Win32 process awareness, `GetDpiForWindow`, and agreement with hldx's per-window display scale. |
| `-DeviceReset` | Heaps DX12's public forced context-loss path, device/context recreation, resource restoration callback, and post-reset HWND responsiveness. |
| `-FocusSelection` | Presses F while the pointer hovers the hierarchy panel instead of the viewport; verifies the selection-based focus command is not gated by viewport focus. |
| `-FovInput` | Clicks the PERSPECTIVE strip, types an exact value into the transform-style FOV field, and verifies probe telemetry reports the committed field-of-view value. |
| `-KeybindingsList` | Opens the native keybindings HWND, confirms all 20 actions in 7 categories are present, then shrinks the window and verifies the binding list becomes scrollable and its list height shrinks. |
| `-ProjectFiles` | Drives the real File menu: Save Project As writes the manifest/scene (including bare names without an extension), the title dirty marker tracks edits, both unsaved-close answers are honored, Open Project rebuilds the saved scene graph, and Save Current Scene on an untitled project routes to Save Project As. Scripted probe paths replace the modal OS picker. |
| `-ImportFiles` | Drives Add → Import Asset in the docked browser with probe-substituted files: a PNG, a JPG named like the reported `Metal049C_2K` maps, and a two-file multi-select batch via numbered `BOLTSPARK_PROBE_PICKER_DIR` answer files. Asserts the multi-extension/native picker call site, on-disk copies directly under `Content/`, `texture` manifest records, browser refresh, decoded thumbnail uploads for both formats, and a `PrintWindow` screenshot (`tests/native/Test-ImportFiles.ps1`). |
| `-ExplorerDrop` | Delivers multi-file Explorer drops to the same production drop handler via a documented `BOLTSPARK_PROBE_DROP_DIR` instruction hook (a cross-process synthetic `WM_DROPFILES` cannot marshal its `HGLOBAL`). Asserts folder placement on `Content/Art`, two copied files and manifest records, and rejection while Play mode is running (`tests/native/Test-ExplorerDrop.ps1`). |
| `-UntitledSession` | Launches with no project and an isolated `BOLTSPARK_PROBE_UNTITLED_DIR` scratch root. Asserts the scratch `Content` folder is visible, Add → Folder writes a folder, Add → Import Asset copies and decodes a texture, and no `.boltproject` manifest is created (`tests/native/Test-UntitledSession.ps1`). |
| `-AssetWatcher` | Waits for the watcher baseline, then writes a file at the scratch root and a folder with a nested file from outside the editor. Asserts each external change produces a `[watcher]` signal and a browser re-scan with a larger entry count (`tests/native/Test-AssetWatcher.ps1`). |
| `-FloatExplorerDrop` | Hosts the Asset Browser in a floating HWND, feeds the native drop latch through a documented probe hook, and asserts a two-file drop resolves `Content/Art`, copies both files, records both textures, and is refused in Play mode (`tests/native/Test-FloatExplorerDrop.ps1`). |
| `-MaterialEditor` | Creates a material through the Asset Browser Add menu, asserts the dockable Material Editor opens with the new document, then double-clicks the material tile and asserts the editor reopens (`tests/native/Test-MaterialEditor.ps1`). The headless `MaterialEditorRepro` covers document round-trip and asset lifecycle. |
| `-AssetBrowser` | Launches the editor with a `.boltproject` argument (the .uproject-style path), verifies the file scan, creates a scene with Add → Scene, renames it inline, and double-clicks a scene to open it. Also creates and F2-renames a root-level folder, copies/pastes an asset with Ctrl+C/Ctrl+V, drag-drops a tile onto a folder for a direct move and with Ctrl for a copy, creates an explicit nested subfolder from a folder's context menu, drags a folder onto another folder to reparent it, checks folder-name rows and collapse/expand, fills the grid until scrolling is enabled, navigates via folder rows, back/forward arrows, and the root breadcrumb, uses the New… submenu to create a nested folder, right-clicks empty toolbar space for the Add menu, dismisses it with a left-click, scrolls with the wheel, and presses Delete on both assets and folders (asserting the folder is actually removed). Also runs `Test-RevealRoot.ps1`, which right-clicks the root "All" folder with no project loaded and invokes Reveal in Explorer to confirm it prompts project creation instead of throwing or opening a stray directory. Checks on-disk files and refresh markers. |

The probes send messages only to the Boltspark HWND. They do not inject global
mouse or keyboard input. They use isolated `LOCALAPPDATA` directories where
layout persistence is involved, so tests do not overwrite the user's editor
settings.

## Performance and memory baseline

```powershell
.\tests\native\Measure-EditorPerformance.ps1 -DurationMinutes 15 -SampleSeconds 5
```

The first minute is idle. The remainder alternates 1280×800 and 1440×900 to
exercise resize/resource paths. The probe records process CPU, GPU Engine
counters when Windows exposes them, working set, private bytes, handles, and
in-application frame telemetry. Results are written beneath
`bin/test-results/performance/`.

## Hardware gates that automation cannot substitute

The current-monitor DPI probe does not prove transitions between physical
monitors with different scale factors. The forced DX12 reset verifies Heaps'
recreation path but is not a genuine driver-triggered `DXGI_ERROR_DEVICE_REMOVED`
event.

The tracked flag `ignoreExternalHardwareValidation` in
`tests/validation-policy.json` currently defers those checks until M9 release
hardening because the required external hardware and fault conditions are
unavailable. Second-machine confirmation was closed on 2026-11-23 on the
project owner's firsthand report that the editor runs successfully on two
additional Windows 11 / DX12 PCs; it is recorded as user-attested because no
per-machine artifacts were retained. The test runner reports the policy on
every invocation. Deferred means non-blocking for current development—not
passed—and the checklist items remain open until real evidence exists.
