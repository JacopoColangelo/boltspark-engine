# Boltspark verification workflow

Boltspark separates tests that can run on a clean hosted worker from tests that
require the pinned native runtime, a real HWND, and a Direct3D 12 GPU. Test
programs and probes are tracked under `tests/`; generated bytecode, logs,
screenshots, CSV files, and JSON results remain under ignored `bin/test-results/`.

## Portable checks

```powershell
.\tools\test.ps1 -Portable
```

This command does not need Neko, HashLink runtime DLLs, or a GPU. It:

1. enforces the native H2D + `hldx` + DX12 dependency policy;
2. compiles the complete application to HashLink bytecode using the tracked
   source classpaths directly;
3. runs the portable arcball, Euler, post-arcball rotation-ring, BoltUI-core, command-history,
   editor-session, component-system, scene-hierarchy, keybinding-migration, and
   project/scene-serialization tests through the Haxe interpreter.

The pinned compiler executable and its five adjacent Windows runtime DLLs are
tracked as one hash-verified set; native HashLink/DX12 runtime modules remain
designated-machine dependencies and are not required by this portable job.

`.github/workflows/windows-ci.yml` runs this path on every push to `main` and
on pull requests.

## Full local regression suite

```powershell
.\tools\test.ps1
```

The default native path first runs `tools/build.ps1 -Check`, then compiles and
runs all portable tests as HashLink bytecode plus the editor-camera navigation
test, Heaps affine scene-object bridge, DX12 `hl.CArray`, and FreeType
native-module regressions. It expects a previous build to have created
`bin/freetype.hdll`.

To rebuild everything first:

```powershell
.\tools\test.ps1 -Build
```

## Native runtime probes

Optional switches add real-window checks:

```powershell
.\tools\test.ps1 -Build -NativeSmoke -CommandHistory -RotationHandoff -WindowLifecycle -DpiProbe -DeviceReset -FocusSelection -FovInput -KeybindingsList
```

| Switch | Coverage |
|---|---|
| `-NativeSmoke` | Development and packaged release HWND creation, icon assignment, positive DX12-driver identity, empty stderr, and clean `WM_CLOSE`. |
| `-CommandHistory` | Native gizmo, Inspector, Create, and Delete commands followed by rebindable Ctrl+Z/Ctrl+Y; verifies transform, renderer-view, identity, and selection restoration in the running DX12 editor. |
| `-RotationHandoff` | Window-scoped center arcball followed by a snapped world-axis torus drag; verifies that the ring changes only its captured axis after an arbitrary freeform orientation. |
| `-WindowLifecycle` | Small/large/baseline resize, maximize/restore, minimize/restore, splitter persistence, empty-space deselection, and cube picking after splitter movement. |
| `-DpiProbe` | Current-monitor Win32 process awareness, `GetDpiForWindow`, and agreement with hldx's per-window display scale. |
| `-DeviceReset` | Heaps DX12's public forced context-loss path, device/context recreation, resource restoration callback, and post-reset HWND responsiveness. |
| `-FocusSelection` | Presses F while the pointer hovers the hierarchy panel instead of the viewport; verifies the selection-based focus command is not gated by viewport focus. |
| `-FovInput` | Clicks the PERSPECTIVE strip, types an exact value into the transform-style FOV field, and verifies probe telemetry reports the committed field-of-view value. |
| `-KeybindingsList` | Opens the native keybindings HWND, confirms all 14 actions are present, then shrinks the window and verifies the binding list switches to a scrollable mask. |

The probes send messages only to the Boltspark HWND. They do not inject global
mouse or keyboard input. They use isolated `LOCALAPPDATA` directories where
layout persistence is involved, so tests do not overwrite the user's editor
settings.

## Performance and memory baseline

```powershell
.\tests\native\Measure-EditorPerformance.ps1 -DurationMinutes 15 -SampleSeconds 5
```

The first minute is idle. The remainder alternates 1280×800 and 1440×900 to
exercise resize/resource paths. The probe records process CPU, GPU Engine
counters when Windows exposes them, working set, private bytes, handles, and
in-application frame telemetry. Results are written beneath
`bin/test-results/performance/`.

## Hardware gates that automation cannot substitute

The current-monitor DPI probe does not prove transitions between physical
monitors with different scale factors. The forced DX12 reset verifies Heaps'
recreation path but is not a genuine driver-triggered `DXGI_ERROR_DEVICE_REMOVED`
event.

The tracked flag `ignoreExternalHardwareValidation` in
`tests/validation-policy.json` currently defers those checks and second-machine
confirmation until M9 release hardening because the required external hardware
and fault conditions are unavailable. The test runner reports that policy on
every invocation. Deferred means non-blocking for current development—not
passed—and the checklist items remain open until real evidence exists.
